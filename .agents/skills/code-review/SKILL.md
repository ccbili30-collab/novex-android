# Novex Code Review

权威协议：仓库 `docs/review/README.md`（含三个审查代理的派发指令骨架、参考技能映射、主 Agent 检查单）。本文件是执行入口，冲突时以协议为准。

## 铁律（先于一切步骤）

1. **bug 先定位后动手**：用户报告缺陷时，先沿链路定位，汇报"病因 + 修法 + 波及面"，经用户确认后才修改。
2. **发布需明确批准**：任何安装包发布、分支合入发布线，必须用户明确指令。
3. **CI 绿 ≠ 行为正确**：编译与单测只证明静态没坏；UI 行为未经用户真机验收前，汇报中如实标注"未视觉验证"。

## 流程

### 1. 范围五问（用户确认后才动）
现象是什么 / 理想状态 / 本轮修什么 / 哪些相关问题顺带修 / 哪些明确保留。

### 2. 全链路定位（只读不改）
沿 `用户操作 → 界面 → ViewModel → 领域 → 仓库 → 数据库 → AI 运行时 → 消息事件 → 渲染` 通读，找到第一个不成立的节点。定位产出写进任务文档（防上下文丢失）。无法从代码确认的，明说不确定，不猜。

### 3. 病因汇报（bug 类必须）
向用户报告：根因（代码位置）、证据、修法、风险面。等确认。

### 4. 实现与自查
- 按完整功能链写代码，不留"前端有入口、底层没实现"；
- **UI 改动附渲染推演**：关键坐标落点、触达区大小、按下/拖动/松手/点击状态机逐转换走查，写进提交说明；
- 语义自查：正常路径、空数据、旧数据迁移、中断/失败/重启恢复、重复触发、覆盖用户内容、导航返回、删除/导出/撤销。

### 5. 分级审查（Agent 工具派发，审查者不改代码）
- **轻**（一行修/文案/参数）：跳过代理，仅主 Agent 自查；
- **中**（单模块逻辑/bug 修复）：+ 整体链路审查代理 B；
- **重**（新功能/跨层/UI 系统）：A 源码对比 + B 整体链路 + C 修复后复查，三代理全开。
代理指令骨架见 `docs/review/README.md`；参考技能原文在 `docs/review/reference-skills/`（tbui-ai / tbui-mb / diagnosing-bugs / code-review / domain-modeling / codebase-design / visual-frontend-replica），按改动性质选读对应份。
意见三分类：确定缺陷直接修；可能风险读码或加验证；产品取舍交用户。与用户已确认结构冲突的意见拒收并说明。

### 6. 本地机械自检（推送前必过）
- `scripts/tests/` 契约测试全过（纯 shell，无需 Java）；
- 全文件扫描：无未用导入、无缺失导入、可空标注核对、组件禁用清单（对照 NovexComponentArchitectureTest 的禁用表）。

### 7. 编译最后 + 编译后核对
推送分支 → 触发 android-validate（app 单测 + 六库模块单测 + 编译）。失败必须读真实日志、说出具体错误行再修。通过后核对：构建提交 = 审查过的提交、渠道/版本正确。

### 8. 验收与发布
用户可见改动附编号验收步骤。发布走已验证候选，不重编。

## 会话习惯

- 推送 GitHub 失败自动重试（网络间歇故障）；
- 大任务先落盘任务文档再动工；
- 汇报格式：先结论，再证据，最后待确认项。
