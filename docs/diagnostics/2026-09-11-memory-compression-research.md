# 对话压缩与原文回查：简短研究记录

最新决策：用户随后选择 Pi（编码智能体工具集）方法，已进一步核对其官方文档与压缩源码并实施；以下是此前有限研究记录，方案以[最新执行记录](2026-09-11-pi-compaction-execution.md)为准。

核对日期：2026-09-11。仅研究官方仓库公开文档；本轮未完成源码逐项核验，不把项目宣传当成实测保证。

## 已核对

- **lossless-claw（无损上下文管理插件）采用“原文存储＋摘要上下文＋按需回查”**：官方说明将消息按会话保存到 SQLite（轻量关系数据库），旧消息分块由大语言模型生成摘要，摘要继续合并为 DAG（有向无环图），每轮上下文由摘要和近期原文组成。这里应区分：存储层保留原消息；摘要本身是有损表达，不能保证模型每轮知道全部细节。[官方说明](https://github.com/Martian-Engineering/lossless-claw#what-it-does)
- **已有模型回查接口**：`lcm_grep`（历史搜索）、`lcm_describe`（摘要描述）、`lcm_expand`（展开回查）；摘要关联来源消息。可将这些机制作为 Novex（应用名）的主要参考，但本轮未核验各接口返回字段、分页和逐字恢复的源码行为。[官方说明](https://github.com/Martian-Engineering/lossless-claw#what-it-does)
- **不能无条件宣称“所有内容永不丢失”**：文档支持排除会话存储，并提供可删除特定心跳轮次的配置。因此“无损”需要限定为成功纳入并保留的原始记录，不等同摘要无损或自动召回完整。[配置说明](https://github.com/Martian-Engineering/lossless-claw#configuration)
- **直接移植不是轻量依赖接入**：插件依赖 OpenClaw（智能体宿主）的上下文引擎及 Node.js（JavaScript 运行时）22 以上版本；文档所列宿主兼容门槛为 2026.7.2-beta.2。因此移植到安卓端需要另做运行时、宿主接口和数据库适配；“借鉴机制优于整套搬入”是基于依赖边界的工程判断，尚无工作量实测。[运行前提](https://github.com/Martian-Engineering/lossless-claw#prerequisites)
- **许可证**：仓库首页标注 MIT（麻省理工学院宽松许可证）；本轮未逐字核对许可证正文和所有依赖的许可证，不将首页标注视为完整合规审计。[许可证入口](https://github.com/Martian-Engineering/lossless-claw/blob/main/LICENSE)
- **pi-mono（原仓库名）发生重定向**：`badlogic/pi-mono` 当前重定向到 `earendil-works/pi`。本轮仅核对仓库归属变化，未完成其压缩源码、原文保存、模型回查工具与许可证正文核对，不能声称其提供无损压缩或现成历史回查。[官方仓库](https://github.com/earendil-works/pi)

## 面向当前应用的建议

采用有限范围方案：原消息继续作为事实来源保留；请求上下文只放“带原文范围引用的分段摘要＋近期原文”；给模型提供会话内搜索和按消息范围读取原文两个受预算限制的工具。不要把摘要覆盖到原消息上，也不要把用户界面的折叠或淡化等同数据删除。这是方案建议，尚未实施或验证。

lossless-claw（无损上下文管理插件）适合作为回查机制主要参考；pi（智能体工具集）仅保留为下一步核对轻量压缩边界的候选，不能在尚未核对时据此承诺能力。无需为当前目标引入跨会话画像、向量库、多级记忆治理或子智能体回查。
