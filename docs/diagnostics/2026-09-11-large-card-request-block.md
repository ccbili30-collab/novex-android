仅诊断，未改产品代码。截图与导出包的卡名不同，不视为同一次请求。

导出包记录为开发候选八：世界卡一个模块、一个文字块，正文 1,737,309 字节、1,146,333 个码点。26 次分段正文读取成功，最大结束位置 700800，并非全文读取完成。一次新增模块被拒绝；最终配置同时采用和管理该卡。后续记录出现与截图相同的上下文准备错误。

配置容量为 1,000,000，运行记录为 128,000；这是软件记录，未验证服务端真实容量。卡片预算代码另取窗口 30%、128000 与剩余容量的最小值。

代码定位：IntegratedCards（卡片接入）的 candidates（候选资料）先按摘录选择模块，再全文读取每个选中块，标为必须携带，预算超额直接抛错。ChatViewModel（对话控制器）在主模型循环前执行这段准备。加入管理不移除采用，因此不能解除全文超额。

诊断依据用户失败记录、成功工具回执和代码，未新增运行复现，不声称修复。后续使用无害合成大文本回归。原包正文不写入文档或仓库。

建议确认范围：超大块以来源目录、有限摘要及现有分页读取衔接；管理请求不被全量采用阻断；明确已携带、可读取、未读完，不静默截断冒充完整采用；核对预算比例与真实窗口约束。
