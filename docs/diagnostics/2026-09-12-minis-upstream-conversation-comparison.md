# Minis 最新公开版与 Novex 对话机制对照

本轮仅源码比较，无业务代码修改、无构建发布、无手机对照验收。不能用差异直接证明全部故障病因。

## 版本依据

上游 https://github.com/OpenMinis/OpenMinis/releases/tag/1.13 ，最新公开安卓版本 1.13；本次 git ls-remote HEAD 与下载的源码均为 4ef29002e88db1e20e462ec2ff46916e8a7dcb45，提交时间 2026-09-02T02:19:16+08:00。本地对象为 card-core-integration 当前工作树（候选十六源码）。上游只读副本及逐文件差异保存在 local/qa/minis-upstream-20260912/，未覆盖产品目录。

## 已确认差异

1. 工具循环：两者都在 ChatViewModel 中通过 for(turn in 0 until MAX_AGENT_TURNS) 调用模型，取得工具请求、执行、保存回执到历史，再进入下一轮。循环不依赖必须提供 shell 或 file_read。
2. 工具清单：上游 AgentTools.makeAgentTools 提供原工具。本地同名注册入口已经改为 Novex 卡片、资料、记忆、存档、快捷操作等；另保留浏览器、看图等部分能力。不是关闭整个执行引擎。agentTools 还按只读权限、模型支持能力、当前卡片绑定过滤。
3. 工具执行：本地 executeTool 增加 Novex 审批、执行记录复用和实际卡片执行路径，不能把登记工具等同于只替换名称。保持参数、调用编号、真实回执与后续历史配对是接入条件。
4. 流式输出：LLMProvider.kt 与上游逐字节一致，基础抽象仍共用；不代表各供应商实现都一致（共同 provider 文件17相同、12不同）。上游在宿主内收集流事件，本地增加 AssistantStreamTurn 负责单次输出、工具参数和重试状态重置，再交宿主发布显示。不能依据工具清单变化断定流式协议被破坏。
5. 折叠：本地新增 NovexExecutionProcessState.foldNovexExecutionProcesses，按用户消息/分支界限聚合可折叠工具、思考、带 executionText 标记的正文；交互结果存在例外。它是额外展示层，关闭原工具并不会自动要求这种聚合。当前代码不是所有正文全部折叠；旧正文误标记已有历史修复，不能重新认定仍全部存在。
6. 卡片发送前准备：本地 runAgentLoop 在进入主循环前调用 prepareNovexRequestContext；IntegratedCards.candidates 包含选料辅助模型、正文分页、目录及管理说明，最后再次校验容量。用户截图中的“本轮剩余上下文不足以携带已采用或管理的卡片资料”对应本地新增检查。原版没有该卡片准备关卡。具体预算哪项不成立仍需本轮请求证据。
7. 压缩和回查：上游 offloadContextIfNeeded 把长工具结果移到文件，以 file_read 提示保留回查入口。关闭 file_read 若保留原机制，会形成不可回查依赖。本地当前遇到新卡绑定直接跳过旧卸载路径，改用 ConversationToolRetention.project 和 read_conversation_history；因此不能把这个潜在依赖描述成候选十六已经确认仍发生的故障。旧对话无新卡绑定的分支尚需单独审计。
8. 大文件本身不是新旧判断依据：上游1.13公开记录也包括压缩限时限次数、响应中断保留、工具图片、流式重解析和崩溃追踪等修复。不能声称上游从无问题，也不能凭最新源码等同实机稳定。

## 结论及建议（未批准实施）

换成自制工具本身不会取消循环或破坏流式能力；替换工具需要同时对齐配套依赖。我们实际改造范围超过工具替换，资料准备、历史容量处理、执行恢复和展示聚合均有变化。当前证据优先支持以原版对话机制为对照整理接入，不支持立即更换整个内核。

后续比较应依次采用无工具普通聊天、一个只读工具、连续两次工具、失败/取消、同工具接入新卡、大卡采用和回查，区分模型响应、实际执行及界面事件。未进行这些差分运行前，不宣称上游正常或当前所有根因已定位。
