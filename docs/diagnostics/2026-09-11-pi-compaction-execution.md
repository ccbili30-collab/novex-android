# 容量保留式对话压缩与历史回溯

## 已确认范围

用户授权按 Pi（编码智能体工具集）的容量保留方法改造原应用对话链。原消息正常保存和显示；近期原文按容量保留；摘要记录明确边界；模型可在允许范围内搜索、读取历史。不是更换整套应用，不引入分层记忆图、向量库、跨对话画像或对话分裂。稳定版不动，不公开发布。

参考：[官方压缩说明](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)、[压缩源码](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/compaction/compaction.ts)。借鉴机制，未复制项目代码；不声称摘要无损。

## 代码责任

- 原消息：原 ChatRepository（对话仓库）、数据库和活动分支保留。
- ConversationRetention（对话保留策略）：按容量选择较早范围与近期原文，保护消息编号和工具调用/结果边界；重建摘要与近期消息。
- ConversationCompactionPolicy（对话压缩策略）：原剧情/通用摘要要求保留；序列化避免同一文字重复计入。
- ChatViewModel（对话状态控制器）：接现有模型调用、容量设置、摘要保存、继续发送、权限与消息分支。新记录 version=3（版本三），同时保存最后压缩消息、第一条保留消息；旧记录继续兼容。
- ConversationRecall（对话回查）：接经过原有分支/权限投影的消息，搜索返回编号与片段，原文读取返回字符分页位置。读取不能授予卡片修改权限，只读模式不提供工具接口。
- ChatScreen（对话页）：默认展示历史，移除压缩灰化；更多菜单里的历史搜索可定位原消息，沿用窗口加载和现有选择弹层；压缩期间有可达停止按钮。

## 手机验收

1. 覆盖安装候选后打开原有长对话，旧消息应正常亮度；进入“对话历史”，搜索早期一句话，点击后应定位原文；返回最新内容应仍可发送。
2. 在长对话发起压缩，观察近期对话保留；停止一次，原文和输入仍在；再次压缩完成后重启应用，继续原话题。
3. 在有工具调用的长对话继续工作：调用和结果不脱节，压缩不会让模型重做已完成写入。
4. 工具允许时询问很早的一句具体约定，观察历史搜索与原文读取；只读模式仍不出现工具接口。
5. 切换较小对话容量后继续，压缩使用当前容量。不能据编译通过断言真实摘要毫无失真。
