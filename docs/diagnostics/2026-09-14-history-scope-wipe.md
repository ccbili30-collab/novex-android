# 诊断：实况会话历史丢失助手回复（模型逐轮复答旧问题）

日期：2026-09-14。状态：已定位并修复（提交见本文件底部），待手机验收。
用户报告最初怀疑"每轮注入"导致上下文累计；核实结果与之无关。

## 症状

连续对话中，模型每轮先把之前各轮的问题重新回答一遍，再回答当前问题；
重开对话后第一轮正常，继续对话后复发。

## 证据（来自用户导出包 conversation-83192302）

- 会话 `per_turn_prompt = NULL`：每轮注入未启用，注入代码路径全程未生效，排除。
- 落库消息完全干净：用户消息各自只含自己的文本，无堆叠、无注入文本；
  分支结构（parent/active_child）正确。
- 系统提示词（资料装配）逐轮稳定 85301 字符，无累计。
- 连续助手回复中"复答"段落为**意译重写**而非逐字复制（相邻回复最长公共块仅
  ~177 字符，即状态栏模板；相似比 0.34–0.42）：模型在重新生成旧答案，
  不是输出被机械拼接。
- 结论：请求历史中**用户消息可见、助手消息不可见**——模型看到一串未回答的
  问题，于是逐轮补答。

## 根因

`NovexScopedConversationHistory.project`（3.0 对话底座引入，**正式版 v3.0.0
即存在**，非 3.0.1 回归）：范围投影对无法验证的消息按落库行重建文本；
`NovexHistoryAccessScope.canReplay(null) = false`，而实况对话循环内追加的
助手消息（ChatViewModel 循环内两处 `agentHistory.add`）**未携带
dbMessageId**，也非用户消息——重建时行与 publicHistoryText 皆空，
正文被置为空串，再被空消息过滤整条丢弃。

用户消息在发送时带 `dbMessageId`（可从落库行重建）、工具结果消息也带
（`persistToolResultMessage` 返回 id），唯独助手正文漏掉——造成
"只见问题、不见回答"的不对称。

## 修复

- 循环内两处助手消息补 `dbMessageId = turnMessageId`（落库行同一 id），
  使实况会话与重开会话走完全相同的重建路径。
- 不改投影本身：`missingRowsDoNotTurnFlattenedExecutionIntoPublicConversation`
  明确要求无行文本必须清空（防执行内容洗白为公开对话），回退会破坏该隐私契约。

## 验收要点

连续多轮对话（不重开），第三轮起模型不得复答第一、二轮的问题；
同一对话重开后行为一致。
