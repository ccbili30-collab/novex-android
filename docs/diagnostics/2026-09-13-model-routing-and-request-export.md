# 模型选择一致性与失败请求导出

## 本轮授权与边界

用户确认修复两项：聊天误用生图模型／显示与实际模型不一致，以及对话导出缺少实际请求和首次失败记录。本轮不发布、不改稳定工作树，不据此重启对话核心重写。

## 证据与病因

- 用户原包 22821f4e 仅有两份提供商调用前装配快照，配置记录写 gemini-3.8-flash，不能证明最终发送目标。用户随后现场发现选到了生图模型；旧包缺少这一步证据，无法还原该次精确路由。
- 发送前原判断只检查缓存连接非空；配置变更后未重新核对选中条目。多处先更新模型名称、后获取凭据和构造连接，失败可留下不一致状态。
- 默认组与旧单步备用选择缺聊天输出过滤；部分中转列表只有名称，缺能力字段，旧设置会保存为文字输出，名称过滤也漏掉 Gemini（双子座）图片后缀。聊天模型与图片输出模型的判断需要共用。
- 旧恢复只按型号取第一个条目，同型号不同连接存在歧义；组选择失败仍可能先改变组标签或保存请求选择而非实际选择。
- 排队续接捕获的是最初连接；自动切换成功后，排队消息仍可能回到旧连接。
- 首轮失败没有助手持久行时，界面错误只留内存，或更新不存在的行；原导出只收当前配置和装配快照。

其中代码缺口已经定位；不能把上述任一项冒充已精确复现用户手机的那一次误选。此前中转空流式工具响应仍是另一个已复现但未定根因的问题。

## 修改

- 共用聊天模型资格判断：排除图片输出、明确生图型号、隐藏及关闭连接；图片输入的文字模型保留。
- 设置保存、默认选择、恢复及备用选择使用同一标准；按条目编号关联具体连接，不凭显示名反查。旧型号重复时不猜第一个。
- 连接构造成功后才更新模型、条目与名称；发送前按最新配置重建连接。生成中的手动切换要求先停止，自动备用切换仍有效。排队消息沿当前成功连接继续。
- 每次运行单独持久保存请求记录：显示选择、实际请求型号、脱敏地址、协议、工具数量、输出预算、返回状态、重试与失败；提供商有返回型号时另记返回值，不把别名当成真实底层模型认证。
- 请求记录独立于助手行；草稿转正式对话时携带前置失败记录。记录写入失败不阻断聊天。
- 导出加入实际请求目录及索引，只导出该对话记录。无历史记录明确注明缺项；不补造旧请求。不保存请求正文、请求头或凭据，错误消息进行密钥脱敏。
- 三类主要传输（开放人工智能兼容、双子座原生、Anthropic 原生）均记录最终构造的地址与请求型号。
