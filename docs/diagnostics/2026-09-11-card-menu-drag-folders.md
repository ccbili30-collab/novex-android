# 菜单、拖动与文件夹正文

## 本轮确认覆盖

用户纠正：三点菜单保留，用于折叠真正有用的操作；不放重复的打开，不使用冗长的导出／删除文案。对话仅有重复删除的更多入口可以取消。拖动应紧凑，可移入横向栏；同级排序与放入内部要明确。模块成为文件夹后，原正文成为同名的真实子模块，内外可分别重命名，不显示“原正文”等说明。

## 代码修改

- 世界／角色库菜单为导出、删除；导出复用既有原生文件处理和系统保存位置选择，不通过打开卡片冒充导出。卡片展示页菜单保留，文字为导出、删除。
- 对话列表只有删除回调，移除无实际作用的更多菜单，保留直接删除及上游确认。不虚构其他功能。
- 拖动浮层只保留紧凑名称和落点反馈，不展示子项大列表。拖动中不展开被拖模块的正文和下属；原有展开记忆保留。
- 横向轨道空位成为有效落点，包含默认主要槽。竖向模块可整体移到顶层横向栏；更多菜单的移动页也提供此操作。
- 中间停留 700 毫秒后才判作放入内部；此前按同级前后排序。排除自身和后代，落下前显示同级排序／放入对象／移到横向栏。
- `FolderContents`（文件夹内容规则）将有下属模块的自身正文移动到真实同名子模块。原块编号、正文引用、图片资源保持；正文模块保留原编号与采用规则，新文件夹编号确定且处理重复时不再拆分，避免原对话按编号保存的选择指向空容器。
- 共同卡片编辑入口处理整理，人工与 AI（人工智能）走同一路径。已有卡仅在编辑草稿内整理；保存比较按同一结构规则比较，单纯查看不触发保存选择。正式卡在保存前不被改写。
- 已保存页面使用相同结构呈现，文件夹与内部正文分别折叠；普通名称不追加内部说明。世界内部角色及从角色库复制的角色采用同一规则。
- 模型说明同步告知文件夹生成后的结构变化，要求重新读取编号后编辑，不继续假设外层文件夹直接持有正文。
