### 卡片目录的具体边界

示意：

```text
某张卡的专属目录/
├─ 卡片.json（结构化卡片文件）
└─ 图片/（有图片时存在）
   └─ 场景图.png
```

1. 用户仍点击一张卡并在模块内放图，不需要理解文件路径或先打开文件夹再找卡片文件。
2. 创作库和库内文件夹是用户组织内容的方式；卡片专属目录是资源归属。一个卡被不同库收录，不生成互相漂移的正文副本。
3. 卡片自己拥有加入的附件。来自其他库或卡的图片默认复制到当前卡；不能偷偷借用一个可能随别处删除而消失的文件。图片直链应下载落地并校验后才称为已保存附件；如保留远程引用，必须显式呈现其外部依赖，不能伪装成本卡已保存内容。此处是建议落地策略，尚未实现。
4. 卡间关系仍按稳定编号定位对应卡片文件；改名、移动不能断链，也不按重名重新绑定。图片采用卡片目录内相对定位，校验越界路径。
5. 新对话三张私有空卡仍全部隐藏，目录存在不代表加载设定或启动文游；可以继续创建任意多张卡。
6. 图片加入模块不意味着每轮发送整张图。模型先按可见权限取得模块目录、说明与候选，需要时读取；仅背景角色的配套玩家身份和专属扮演指令保持隔离。
7. 删除、复制、回收站、导出、导入与缺失文件一起设计：保留独立卡片和既有共享图片；卡包携带自身附件，外部卡依赖明确列出；编号重映射、循环引用和游玩快照不得受损。
8. 实施前明确卡片文件与现有数据库谁是正文的唯一权威来源、谁是可重建索引。不得双份独立修改。设计原子提交、失败恢复、旧格式兼容和迁移回退后，再切换真实调用；不为模拟文件夹而重写无关系统。

### 剧情插图的最小可用流程

作者进入卡片模块 → 添加图片与简短说明 → 可选配置触发条件 → 预览；游玩中检索当前可用候选 → 确定本轮选图 → 回复内实际显示 → 保存本轮引用 → 重开仍显示同图。

首批区分“确定条件展示”和“人工智能按语境选图”。明确扫描用户消息还是已生成回复、匹配范围、多个命中、冷却与去重规则后实施；不能把关键词命中等同于已经渲染，也不让图片描述递归触发无限调用。不引入对用户创作意图的固定动词判断。

现有基础图片语法可以显示图片地址，世界书仅有部分基本触发。酒馆截图中的随机宏、图片短编号替换及朋友圈模板尚未贯通，不能称为已有功能。

### 第一批：成果与存档可信，首次使用不退出

顺序为问题 01、02，随后 03、04；服务退出同样是本批发布阻断项。

| 排查对象 | 必须核对的衔接 | 验收要求 |
| --- | --- | --- |
| 成果打开 | 实际回执编号 → 类型与角色版本 → 导航参数 → 内容加载 | 回答按钮与卡库打开同一已有对象，名称和全部模块一致；世界／角色／文游均检查；缺失对象说明失效，不落到空白创建页 |
| 正式存档 | 工具参数 → 会话／分支 → 实际保存文件 → 格式识别 → 列表 → 详情 → 续接读取 | 批准后列表立即可见；重开仍在；能从存档读取并实际续用当时地点、物品与原始事件；其他分支不串档；失败不返回成功 |
| 无模型新建 | 新建会话 → 服务启动时序 → 空连接分支 → 异常及恢复 | 无模型可进入空白对话并看到连接入口；新建本身不需要模型；尝试发送才给可处理提示。连续三次新建不退出，已配置模型路径不受损 |
| 空面板 | 实际参数 → 校验与转换 → 消息保存 → 面板绘制 | 有内容实际显示；只有标题不能冒称已展示地点线索；修正参数或给明确失败。重开后内容仍可见，查看不推进回合 |

每项先提出可被反例推翻的原因，再用原失败过程和针对性测试判断。存档不靠放宽分支过滤使列表“看起来有了”；面板不靠补空白占位文字过关；成果不靠重新创建一个同名副本。

图标可以随本批验收，但需真实安装后检查亮暗主题、桌面裁切和升级保留；不得用资源编译代替安装包验证。

### 第二批：自然语言操作与界面状态一致

复用现有身份选择和文游启动动作，使模型在明确的用户意图下通过正式操作提交状态。先查工具是否缺入口、返回约定是否不足、执行是否没有更新界面，再决定修改位置；不重新增加固定动词路由。

- “创建角色，以后想聊天”只创建，不提前切身份；“现在和该角色聊”选定真实角色版本，设置、下一次请求和重开后一致。
- “整理这张文游”只管理；“开始玩这张文游”提交唯一活动文游及规定身份，再开始叙事。切换已有身份／玩家选择的冲突按既定规则明确处理，不能静默拼接。
- 批准模式使用现有统一批准入口；只读不提供工具且不谎称改了配置；自由不加额外批准。暂缓的勾选行为不混入本批。
- 用户可从成果或详情使用清楚的“与角色对话”“开始游玩”入口；复用已有入口或修正导航，不堆重复按钮。
- 同时验证不替玩家行动、查看状态不推进剧情、正式回答不输出内部编号或把失败说成成功。
- 问题 09—13 先复现与界面审阅，采用局部比例、名称和入口改进，维持原视觉体系与四组设置。

### 第三批：卡片所属文件与模块图片

依赖第一批的可信保存和成果定位。先提交可审阅的存储／迁移设计及旧样例转换验证，再逐步接入卡片保存、图片添加、预览、重命名移动、复制导出和恢复。每一步都含实际用户入口，不先造一套模型能写而界面看不见的存储。

### 第四批：剧情选图与展示

依赖第三批。先完成一张卡内的本地图片和直链落地、简单条件展示与选图、消息内显示及重开固定。再考虑多图候选、随机与模板；不将全面酒馆兼容、时间线地图渲染、任意模板编辑器混入首批。

### 独立质量线：长资料与产品教学

保留十万字失败题，定位原文、章节笔记、综合整理、最终回答的事实变化。原样例通过后再恢复百万字和跨模型交接；逐级估算时间及调用费用，不以旧费用授权省略预算记录。新提示词需真实对照和管理任务验收，第六版不得因软件修复而直接转正。

## 六、测试、模块边界与交付门槛

1. 建立真实操作全过程：普通描述建卡 → 回答打开 → 精确改单模块 → 明确选角色 → 明确启动文游 → 一轮行动 → 查看状态 → 存档 → 退出重开 → 找回并续用。分别记录界面状态、实际保存与下一次模型读取，不能只看模型说了什么。
2. 组合覆盖三类卡、三档权限、无模型、中文输入、已有内容升级与空白安装；不同分支的存档、背景和管理范围不能串用。软件可控回复检查与真实模型语义检查分开报结果。
