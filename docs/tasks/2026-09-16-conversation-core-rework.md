# 会话核心重整（conversation-core rework）

状态：进行中（PR 0）· 方法论已由用户确认（2026-09-16）
总任务书索引：PR 0 见 [2026-09-16-conversation-core-pr0-seismograph.md](2026-09-16-conversation-core-pr0-seismograph.md)

## 背景与根因

conv9 导出包铁证：队列注入路径发出了近乎空的请求（input ≈ 39 token，DB 里有完整历史与图片，
模型回复"当前对话中似乎没有图片"）。根因不在单点，在结构：

1. **双真相源**：内存 `agentHistory` 与 DB 消息树各自为政，无同步契约；
2. **8 个发送入口**（新发/重试/队列注入/恢复/压缩后续发/回传/文游启动/分支切换）各自维护到达
   `runAgentLoopBody` 的内存历史，没有单一组装出口（现状：全部汇合于 ChatViewModel 的
   `streamMessage` 单点，但到达路径各自组装）；
3. **无不变量断言**：请求发出前没有任何"历史守恒/图片守恒/工具配对"检查；
4. **功能层越界**：卡片挂载、骰子/账本/文风注入、图片预算、卸载替换、侧边快照直接伸进组装路径。

## 总纲（对照参考：mini 骨架 / Codex Thread-Turn / DeepSeek Harness）

三家收敛出的成熟形状，五句骨架：

1. **唯一入口的状态机**：对外只有 submit / interrupt；排队、重试、恢复都是机器内部状态转换；
2. **只追加日志 = DB 消息树 = 唯一真相源**：每轮请求从真相源投影装配，内存历史降级为缓存
   且唯一写者是状态机；
3. **装配线是纯函数**：活跃路径 → LLM 消息 → 投影（压缩/图片预算/工具保留/侧边快照，按声明
   顺序）→ 注入插槽（数据而非 if）→ 出口断言 → Provider；
4. **能力只有三种插槽**：注册的工具 / 注入的数据 / 投影规则；谁都不许自己接线发电；
5. **内核吐类型化事件，UI 纯渲染**。

抄形状不抄尸体：Kotlin/Room/Compose + 分支消息树 + 多厂商 + 图片预算是我们的现实，
没有现成代码可整段搬。Minis 的骨头（Provider 抽象、消息树 DB）符合该形状，保留；
烂掉的是 ChatViewModel 内的入口分叉与功能乱接线，换掉。

**硬验收**：重整 PR 中功能模块（cards/、侧边、文游、预设）零 diff。
ChatViewModel 内的功能调用点可以搬家，语义不变。做不到 = 切分错了，回去重切。

## 方法论（映射 docs/review/README.md 三代理协议）

本重整沿用仓库既有审查协议（`docs/review/README.md`），角色映射：

- **主笔**：写代码、修复审、维护台账，对完整链路负责；
- **净眼**（= 协议 A 源码对比 + C 修复后复查）：上下文干净的局部审查 Agent，按阶段任务书审
  "这段代码自身对不对"——逻辑、边界、协程状态、泄漏；必须走场景链路、跑编译测试，不是只读；
- **守纲**（= 协议 B 整体链路审查）：全局审查 Agent，按六问裁决"这段代码跟整体合不合"。

**单阶段生命周期**：用户批准任务书 → 实施 → 自测 → 净眼审查 → 修复闭环 → 守纲裁决 → CI 绿 →
用户批准发布 → 下一阶段。退回规则：净眼查出结构性问题退回实施；守纲否决退回任务书。

**产物四件**（每阶段一套，任务书文件内维护）：阶段任务书（范围/不变量/净眼审查任务书三合一）、
净眼审查报告、守纲裁决书、闭环台账（每条结论三分类：采纳已修 / 驳回留理由 / 挂账记去处）。

**升级规则**（停下找用户）：架构方向分歧；需要动功能模块文件（默认只读）；发布节点；策略级选择。

**守纲六问**：①功能模块零 diff 达成没有？②有没有代码绕过装配线、私开发送入口？
③有没有新旧路径并存（抄一半）？④有没有局部过度工程？⑤与三种插槽模型冲突吗？
⑥上轮裁决兑现了吗？

**红线**（全程有效）：推送前后 git ls-remote / gh api 双通道核对远端 HEAD；squash 合并后
force-with-lease 带旧值；合并前核对 PR 文件清单（不多不少）；审查结论不闭环不进下一阶段。

## 出口断言合同（PR 0 起生效，PR 2 后成为内核合同）

任何入口、任何时候，发给模型的请求必须满足：

- **I1 历史守恒**：主线会话无压缩标记时，请求历史条数 ≥ DB 活跃路径实质消息数（扣除 pureChat
  合法减项）；压缩进行中 / 侧边 / 预期 <2 条时降级为日志；
- **I2 图片守恒**：本轮用户消息带附件图 ⇒ 请求至少一个图片块；
- **I3 工具配对**：每个 ToolUse.id 有 ToolResult.id 配对，反之亦然。

违反 = 拒发（用户可读报错）+ audit 事件 + wire-capture note 行。
