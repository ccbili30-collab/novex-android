# Novex 长篇创作基础版执行计划

更新日期：2026-09-04
当前基线：`a37da54`，`next` 预览分支

## 一、交付目标

本轮把 Novex 从“世界与角色页面”推进为可以支撑长篇共创和文游的统一内容系统：

1. 会话、世界、角色和文游形成四个同级入口；
2. 世界、角色和文游复用同一套内容页面骨架与模块行为；
3. 一段统一对话可以分别配置回答身份、背景设定、管理对象和图片生成指令；
4. 文游拥有可分享的项目格式、分支化本局状态和可见快捷操作；
5. 超长内容按模块检索并进行可追溯的对话蒸馏；
6. 对话产生的文档、图片、地图和卡片进入用户可管理的创作库；
7. 人工智能通过与界面相同的领域命令管理内容，不能直接写数据库。

## 二、已锁定的产品关系

### 统一对话

Novex 只有一种对话。通用交流、角色扮演、世界共创和文游运行都是同一对话的不同配置，不建立互斥的对话类型。

### 对话配置

```text
一段对话
├─ 回答身份：Nova 或一个角色版本
├─ 对话独立系统提示词
├─ 背景设定：多个世界、多个参考角色
├─ 玩家身份：零个或一个
├─ 活动文游：零个或一个
├─ 管理对象：多个世界、角色、文游和文档
├─ 快捷操作：多个
├─ 对话外观
└─ 图片生成系统提示词
```

背景设定与管理对象不能合并：

- 背景设定影响人工智能如何理解和回答，默认只读；
- 管理对象界定人工智能可以定位和修改哪些项目，不自动成为故事背景；
- 同一对象可以同时具备两种关系；
- 多个背景世界保持各自边界，可以共同形成跨世界叙事；
- 多个玩法需要组合进一个文游，一段对话最多运行一个活动文游。

### 内容格式

- 世界卡继续使用 `.novexworld`；
- 角色卡继续使用 `.novexcharacter`；
- 文游卡使用 `.novexgame`；
- 三种格式均为包含清单、主内容文档和媒体的完整归档；
- 导入必须先校验和预览，再通过领域命令原子写入；
- 未知模块必须保留，重名默认创建副本；
- 导入不得触发模型、工具或外部副作用。

## 三、依赖边界

```text
页面
  ↓
Novex 领域命令
  ↓
内容存储／媒体存储／上下文组合／对话运行时接口
  ↓
Minis 适配器
```

- 新页面不能直接访问数据库；
- 人工智能工具与页面必须调用同一组领域命令；
- 背景检索只读取内容，不执行工具；
- 管理对象只提供授权范围，不把完整内容自动放入模型上下文；
- 正式卡片、本局状态、对话记录和创作成果必须分别持久化。

## 四、实施检查点

### 检查点 0：领域与接口基线

建立可测试的纯领域模型：

- 回答身份；
- 背景设定关联；
- 管理对象关联及只读／可编辑权限；
- 活动文游快照；
- 快捷操作定义；
- 本局状态；
- 创作成果及来源关系；
- 上下文引用记录。

测试必须证明：同一对象可以同时作为背景和管理对象；移除一侧不影响另一侧；回答身份始终只有一个；活动文游始终至多一个。

### 检查点 1：四入口与共享内容骨架

- 把底部入口切换器从固定三个升级为可扩展入口，当前为会话、世界、角色、文游；
- 保持点击、展开、空白收起、拖选、跟手横滑和边缘返回语义；
- 顶部栏在四个根页面之间保持位置与动作稳定；
- 将文游接入现有展示、编辑、预览、图片和模块排序骨架；
- 世界、角色和文游只提供各自字段及业务模块渲染器，不复制页面框架。

### 检查点 2：文游项目闭环

实现：

```text
文游目录
→ 文游展示
→ 文游编辑
→ 文游预览
→ 保存
→ 导出／复制全文／分享到对话
```

首批预设模块：

- 固定玩家身份；
- 用户自建身份；
- 先共创世界再游玩；
- 自由沙盒；
- 开局说明；
- 叙事规则；
- 力量、属性、技能、装备、物品、任务、检定和结局；
- 角色档案与状态面板；
- 快捷操作；
- 自定义模块。

地图第一阶段允许只使用一张图片和可选说明，不扩大为可交互地图编辑器。

### 检查点 3：对话编辑页

按以下顺序重做对话配置：

1. 回答身份；
2. 本对话独立系统提示词；
3. 背景设定与玩家身份；
4. 活动文游；
5. 管理对象；
6. 快捷操作；
7. 头像、气泡和背景等对话外观；
8. 图片生成系统提示词。

必须支持：

- Nova 与一个角色版本互换回答身份；
- 切换身份不删除本对话自定义指令；
- 多个世界和参考角色作为背景；
- 多个世界、角色、文游和文档作为管理对象；
- 同一对象同时出现在两个区域；
- 保存前显示实际变化，返回时执行统一草稿确认策略。

### 检查点 4：文游运行时与快捷操作

- 文游启动后仍进入统一对话；
- 文游项目形成对话快照，后续共享项目修改不无提示改变旧对话；
- 文游预设、人工智能动态注册和用户手动添加的操作统一呈现；
- 操作支持添加、编辑、删除、启停和排序；
- 查看型操作不推进剧情，行动型操作产生新回合；
- 动态操作默认属于本局，写回共享文游必须明确确认；
- 本局状态按消息分支保存，切换分支恢复相应状态；
- 切换分支不重新执行工具或外部副作用。

### 检查点 5：上下文组合、计量与蒸馏

每轮请求按以下来源组合：

```text
回答身份
＋本对话指令
＋近期活动分支原文
＋相关背景模块
＋章节／故事线摘要
＋本局状态
＋本轮工具说明
```

实现顺序：

1. 模块名称、别名和结构化关系的确定性召回；
2. 一次有限关系扩展；
3. 模块级统一词元预算；
4. 单个超长条目的段落级分块；
5. 数据积累后再评估语义向量检索。

界面提供：

- 设置中的“显示上下文用量”开关；
- 对话页小圆点、百分比和进度圆环；
- 本轮使用量与有效上下文窗口；
- 每条用户消息下方的引用模块摘要；
- 可展开的上下文引用记录；
- 因预算不足而跳过的条目及原因。

蒸馏不得覆盖原始消息或正式作品。创作领域蒸馏至少保留人物关系、时间与因果、伏笔、文体、世界状态、本局数值、已确认决定和正式模块定位。

### 检查点 6：创作库

应用内建立统一创作库，可按对话、世界、角色、文游和内容类型查看同一批成果：

- 文档；
- 图片；
- 地图；
- 卡片归档；
- 其他工具产物；
- 收藏与回收站。

每段对话提供“本对话文件”入口。工具生成的文件自动进入来源对话；普通短回复不自动变成文件；明确的章节、设定文档和图片成为可版本化成果。

同一成果只保存一次，通过引用出现在多个位置。删除来源对话不能删除仍被世界、角色或文游引用的成果。

第一阶段提供手动导出和用户选择的设备创作目录，可选自动复制；不实现外部目录双向实时同步。

### 检查点 7：人工智能管理工具

在管理对象授权范围内，人工智能可以：

- 创建、读取和修改内容模块；
- 调整模块和条目顺序；
- 创建文档、图片和地图；
- 把创作成果附加到指定模块；
- 创建角色、角色版本和文游；
- 注册快捷操作；
- 建立或解除内容关联。

所有写入先形成结构化变更；共享修改显示影响范围；危险或跨项目操作需要确认；工具不能直接写数据库或直接修改归档中的结构化数据文件。

### 检查点 8：五人长文压力验收

覆盖：

- 至少 200K 词元级对话；
- 百个以上模块和超长单模块；
- 多背景世界跨世界叙事；
- 世界、角色和文游同时作为背景与管理对象；
- 多轮蒸馏后的事实、人物关系、时间线和伏笔保持；
- 文游本局状态与快捷操作跨重启、跨分支恢复；
- 世界卡、角色卡和文游卡导入导出往返；
- 文档和图片引用保护；
- 360 和 412 密度无关像素宽度、软键盘、长文本和图片；
- 真实模型的上下文上限、费用、延迟和降级提示。

## 五、本轮明确不做

- 多角色共同发言的群聊；
- 多个文游同时作为活动运行时；
- 可交互矢量地图编辑器；
- 外部创作目录双向实时同步；
- 人工智能无确认改写共享内容；
- 为文游另建一套聊天正文；
- 为新增页面复制世界或角色页面组件。

## 六、提交、构建与验收节奏

- 只在预览工作树的 `next` 分支开发，不修改稳定工作树和正式分支；
- 每个检查点独立提交，数据迁移、页面、运行时和发布文件不混装；
- 主线执行失败测试、实现和自动测试，不反复安装与手动点击；
- 一批改动只生成一次预览候选包；
- Windows 构建主机承担增量构建和单元测试快速通道；
- 点击、手势、软键盘、系统返回和窄屏验收交给用户或独立验收线；
- 未达到自动测试和静态边界要求时不发布候选；
- `tmp/` 只存临时证据和素材，不整体提交；
- 未经明确要求不推送、不发布、不修改正式版本历史。
