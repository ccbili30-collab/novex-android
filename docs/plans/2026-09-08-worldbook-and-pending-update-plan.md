## 2. 不再改写的产品关系

- 一段对话只有一个主要回答身份、至多一个活动文游；可以参考多个世界和角色，也可以管理多张世界、角色、文游卡。
- 作为背景、作为回答身份、允许管理是不同用途。选用世界书不授予编辑权限，也不切换回答身份。
- 三张私有空卡是隐藏的创作目标，不是用户库中的作品，不在选择器中出现；不限制继续创建更多卡。
- 创作库及其文件夹负责组织；卡片专属目录负责卡片和附件归属；引用指向目录内的卡片本身，不把整个文件夹作为身份或背景。
- 采用设定不等于每轮全文发送；目录、检索、按需读取和实际采用记录要一致。
- 人工智能使用标准工具执行用户意图，不能重新引入固定动词判断。“创建”“扮演”“启动”通过不同动作明确保存。
- 三档权限沿用现有规则：只读不提供工具调用；批准使用统一审批入口；自由不额外审批。应用自己准备已选背景不属于模型偷偷调用工具。
- 保存成功必须有实际成果与可打开入口；执行过程继续折叠，失败与待批准不能被折叠藏住。
- 第六版提示词仍是未验收候选。特殊地图、时间线渲染及万能编辑器不进入这次主线。

## 3. 第一批：先让现有操作可信

### 3.1 对话仓库：界面和人工智能读同一个地方

**已核实的源码事实**：导航打开仓库时捕获原始对话参数；新建对话可能已转换成真实保存编号；准备文件和工具读取采用实际编号。当前准备回调不把实际编号返回给导航。该差异是待复现候选，不是已证实的这次用户个案根因。

**实施步骤**：

1. 用空白新对话导入三份带中文文件名和子目录的资料。通过真实页面打开目录、预览，再让实际工具列目录、搜索和读取；记录各环节对话编号、文件归属和返回数量。先取得同一过程的失败证据。
2. 核对保存对话、导入登记、解析索引、工具可见范围、分支过滤这五个边界；不因发现编号候选就跳过其他环节。
3. 如候选成立，将“准备仓库入口”的结果改为已保存对话的明确地址，由导航、导入、登记和工具共用。异步准备未完成时显示准备状态，失败留在当前页面并给重试。
4. 已有错误归属只在草稿与真实对话映射可以证明时恢复；同步处理原件、解析副本、登记与保护引用。无可靠映射则保留原文件，提供用户可见的重新归属入口，不按名称或时间猜测。
5. 同时审查普通文件工具是否仍把临时气泡编号当成分支；只有复现对应错位才修，不能靠取消分支隔离让资料“都能搜到”。

**用户入口**：对话菜单 → 对话仓库，入口名称与目录结构沿用。输入框附加文件与仓库导入的归属应一致；仓库导入不自动发送消息。

**验收**：三份文件在界面和同一对话工具中都能找到，按路径读取内容一致；退出重开仍一致；其他对话不可越权读取；中文层级不丢；模型不能因软件范围错位反复要求重传。测试区分“工具实际返回空”与“模型有返回却误读”。

### 3.2 弹窗：关闭后真正恢复下层操作

目前只有用户复现描述，尚未定位。先复现“创作库 → 子文件夹 → 归入卡片 → 完成／关闭 → 点击设置和底部导航”，记录仍存活的弹窗、遮罩及触摸目标。

拟优先检查选择器状态是否由多个独立开关控制、父子层是否同时持有窗口，以及关闭动画后是否仍有拦截层。只有证据支持时才合并状态，不能用全局关闭全部弹窗或强制重建页面掩盖问题。

改动目标：同一选择流程尽量在一个弹层里切换列表和目录；返回上一级保留选择；“保存选择”提交并结束该流程；取消及外部关闭丢弃未提交选择；关闭时清理该流程自己的窗口。系统返回先关闭键盘，再退当前临时层，不遗留透明窗口。

**验收**：保存、取消、外部点击、系统返回、快速重复点击各跑原生触摸流程；关闭后第一次点击设置或底部导航即响应。检查亮暗模式白线回归、搜索键盘、中文输入、旋转和大字体；原有白线修复不重复重做。选择草稿、底层滚动位置与进行中的模型任务保留。

### 3.3 模型服务请求：先确认服务，再修专属适配

外部截图不足以证明本应用的请求缺失。先区分 OpenCode Go（订阅模型服务）、现有免费模型目录和用户自定义兼容接口，核对实际地址及请求构建路径。

本次查到的[官方使用范围](https://opencode.ai/docs/go/#where-can-i-use-it)明确要求稳定的会话请求头和应用自身客户端标识，同时面向编程代理请求。这里要验证文游用途是否适配；不能伪装编程流量，也不能将添加请求头当成服务已兼容的证明。缺头要求已证实，09-06 的具体变更日期和用户个案根因尚未证实。

使用本地可控服务捕获脱敏请求，检查普通发送、流式发送、同轮工具后续请求、重试、新对话和模型连接测试。官方规则与实际入口一致后，再加入该服务专属请求适配。会话请求头使用不含用户名、标题和密钥的稳定标识，同一逻辑对话保持稳定，不同对话分开；没有对话的连接测试采用独立测试标识。最终生命周期以官方协议核对为准。

不能向所有服务统一添加专属头；不能伪造浏览器或其他客户端身份；不能把服务失败吞成空回复。必须显示可操作的服务错误，并保留用户输入。

**验收**：目标服务的相关请求覆盖一致，其他服务请求不变；认证信息不进日志；本地协议测试通过后才在已配置目标服务上做一次有限真实验证。没有匹配配置时明确标记真实服务未验收，不阻塞其他独立修复。

### 3.4 审批与记忆的边界

审批勾选行为仍暂缓。保留未来可独立应用的改法：勾选只改选择，确认按钮才提交，提交后只能消费一次，拒绝／关闭不执行，过期请求不能执行。若要恢复实施，需要用户解除此前明确的暂缓决定；讨论计划不等于解除。

记忆本次是回归重点：写入后立即读回、同轮后续请求可见、重开可见、切换身份隔离、重复执行不多写、失败不声称记住。普通回复不得再让用户复制内部确认短语。记忆正文与执行事实检查分开，不把模型一句“记住了”当证据。

## 4. 第二批：文游直接选用已有世界书

### 4.1 界面怎么用

文游卡提供“使用的世界书”入口，放在现有内容概览中，以已选数量或几条短名称显示；完整选择进入次级页面，不往首页再加一组大块内容。现有“关系与使用”保留高级引用与反向索引，同一条关系只保存一次。

```text
文游《邮差入镇》
  使用的世界书                         选择世界书
  文风视角                             已启用
  众生相·造物手札                       已启用
  小镇怪谈                             已关闭
```

选择页：世界库中真实入库内容 → 搜索／创作库筛选 → 多选 → 保存选择。默认整张卡，行内详情才提供选模块／条目。没有内容时显示“世界库暂无内容”，不混入内部索引、临时文件、私有空卡或其他人无权访问的卡。长名称最多两行，详情显示全名，内部编号不进入普通列表。

对话设置继续四组，不新增平级大分类：

| 设置组 | 本次位置与职责 |
| --- | --- |
| 身份与回答 | 诺瓦、自定义或具体角色；本次选书不改它 |
| 使用的设定 | 当前文游、本局使用的世界书与背景；可查看实际采用版本 |
| 内容与工具 | 对话仓库、可管理内容、三档权限；与选书独立 |
| 其他设置 | 外观和既有其他设置；不堆世界书技术参数 |

文游卡修改的是以后启动时的默认选择；对话设置修改的是本局。更改本局时显示简短范围说明，不自动反写共享文游。开关在编辑草稿中变更，保存成功后才成为实际设置。

### 4.2 数据和运行如何衔接

已查代码：`NovexCardReferenceSection.kt`（卡片引用界面）可选世界及模块，但只有替换和移除，没有启停；`NovexGameSnapshotAssembler.kt`（文游快照装配）已有背景／规则引用展开；`NovexTavernWorldbook.adopted`（酒馆世界书采用入口）仅提取当前回答角色附带的一本世界书。不能只改界面。

拟复用带用途引用，加入正式的启用状态和必要的采用策略；不另建一份名称关联表，也不把运行字段塞进“未知数据保留”字段。旧引用缺省保持现有行为。普通背景引用与带触发规则的世界书条目明确区分。

运行顺序：

1. 选定卡／模块／条目，以稳定编号保存引用及顺序。
2. 启动文游时冻结已选来源、修订、触发配置和开关；保留关闭项以便本局开启，但其正文不进入模型请求或背景读取。
3. 本局变更以一个完整配置提交，下次请求使用新配置；已经发送的请求继续使用自己的配置版本，不在流式回答中途换设定。
4. 发送前从当前本局、当前分支可见正文评估触发条件，按统一预算选择实际内容，再生成来源记录。
5. 保存存档时同时保存本局选择、采用修订和需要持续的触发状态。续接恢复这些值，不根据库里最新内容重新猜测。

多个引用路径指向同一来源、同一修订、同一条目时去重；来源不同但同名不能合并。同一来源出现不同采用修订时显示冲突，由明确刷新选择解决，不静默混搭。循环引用沿用已有有界遍历；缺失目标保留名称和失效状态，不自动绑定同名卡。关闭一条引用仅关闭该路径；其他仍启用的路径须在详情说明“仍由另一来源使用”。

角色附带世界书保持原来的角色适用范围。作为背景加入角色，不因此激活其专属扮演指令或配套玩家身份。若作者希望独立复用其中公开设定，应显式整理成独立世界卡，不能把角色私有模块自动开放给其他场景。

### 4.3 首批触发范围

首批提供：条目启停、常驻、普通文本关键词、明确的扫描范围、稳定顺序和总预算。现有支持继续兼容；多书共用一个本轮上限，不能每多一本就无限扩大上下文。

原本普通文本模块继续按普通资料使用；不能猜它的关键词。已有导入条目有受支持的触发字段时保留其语义；只有正文的世界卡允许作者在模块中明确补条件。含不支持条件的导入条目保留原件并显示具体原因，不悄悄改成常驻。首批不承诺完整酒馆兼容，不引入递归、任意脚本或全套宏。

未命中的条目正文不经搜索、摘要等旁路自动送给当前游玩；管理时可以在用户指定的管理范围内查看原件。来源详情给出“已使用、未命中、已关闭、超出预算、配置暂不支持”，主对话只给简洁的已用来源入口。

**验收场景**：同一本书供两张文游使用，一处关不影响另一处；同局多书可用；无角色身份也可使用独立世界书；关键词未命中不进入本轮、关闭常驻不进入本轮；只改一个模块仍保留其他模块；改原卡不改变旧局；显式刷新后才更新；存档重开保持本局选择；多路径去重、缺失、同名、循环和预算边界有可核对结果。

### 4.4 人工智能也能完成同一操作

在现有标准操作体系中提供查看选择、修改文游默认选择、修改本局选择三个清晰动作，返回目标、实际生效范围和可打开入口；前端与工具调用同一领域命令。只读模式不通过聊天偷偷保存设置；批准与自由沿用统一权限。

“给这张文游采用文风视角”默认改指定文游；“这局先关掉文风视角”只改本局。确有两个同名候选时再让用户选择；普通引用不要求用户解释内部编号、文件格式或启动类型。

## 5. 第三批：每张卡一个目录，模块里直接放图

### 5.1 目录及唯一保存来源

用户视角仍是一张卡，直接进入模块添加、排列和预览图片。底层目录示意：

```text
卡片专属目录/
  卡片.json（结构化卡片文件）
  图片/
    雾中镇口.png
```

现有卡片和模块以数据库为主要存储，`NovexWorkspaceFactory.kt`（工作区工厂）已经组织数据库事务和媒体文件提交；`NovexSnapshotMediaStore.kt`（快照图片存储）已有独立保留副本。不能为了目录效果建立第二套可独立修改的正文。

**建议首期保持数据库为唯一写入来源**，卡片目录中的结构化文件是同一修订的受控完整镜像，所有编辑和导入都通过统一保存命令；不提供绕过软件直接修改镜像的双向实时同步。引用仍以卡片身份解析到卡片记录及对应文件，目录移动不改变身份。此方案满足实际专属目录和可打包文件，同时避免一次迁移全部读取系统。若未来开放外部编辑，再单独设计“导入修订和冲突处理”。

保存协议须在实施前用样例验证：暂存附件和完整卡片文件 → 持久记录待提交操作 → 提交数据库修订 → 原子替换完整卡片文件 → 核对修订和资源 → 标记完成并通知界面。跨数据库和文件系统不能假装天然原子；中途退出由恢复记录继续完成或回退，未完成不返回“完整保存成功”。旧修订保留到新修订及附件可核对，磁盘不足不能先删除旧内容。

旧卡先复制构建专属目录、对比模块正文／顺序／引用／媒体校验值，再登记迁移完成；分批可恢复、重复运行不重复创建卡。角色根与版本关系保持：每个可引用版本有明确的卡片载荷归属，根关系仍是一份，不因文件夹拆出多个无关角色。

### 5.2 图片入口和资源归属

模块编辑 → 添加图片 → 本地选择／创作库选择／粘贴图片直链 → 预览 → 保存。使用现有模块编辑和排序，不新增第四种顶层卡，不建万能编辑器。

从其他库或卡选择图片，默认复制进本卡目录并保存来源；不暗中借用随其他卡删除就失效的路径。直链只有在下载、格式校验和落地完成后才称为本卡附件；分享网页地址不能假装是图片直链。下载失败保留编辑内容，提供重试或换来源，不显示“已保存图片”。远程动态引用如后续开放，必须显式标为外部资源。

文件名显示友好名称，内部唯一定位独立存储；目录内用受控相对路径，防止越界，限制文件体积与像素尺寸。模型先取得图名、说明和引用，需要看图才读取，不把图片自动逐轮发给模型。

卡片删除、复制、回收、导出、导入与旧局资源保护必须同批接通。卡包带本卡附件，跨卡依赖列明并重映射编号；旧局与旧消息使用受保护的图片副本，删除源卡不破坏已经保存的游玩。垃圾清理只回收没有任何保护引用的资源。

**验收**：无图卡也有完整卡片文件；图片在模块中看得见、排序后重开不变；改名移动不断引用；复制卡后独立修改；导出到另一测试环境导入仍有图；删除原卡旧存档仍能看图；失败、断电式退出、磁盘不足不会产生“数据库成功但文件丢失”的假完成。

## 6. 第四批：剧情自动展示已有插图

依赖第三批的可靠图片归属和第二批的采用／条件机制。不是临时生图，也不靠模型随意拼接网址。

作者在图片条目填写短名称、说明和可选关键词；可以不配条件，让人工智能从本局可用候选按语境选择。展示只在回复里出现实际图片，内部资源编号不出现在普通正文。

首批自动触发规则建议固定为：只检查本轮完成后的可见剧情正文，不检查推理、工具返回、隐藏设定和图片自身说明；直接一次匹配，不递归。显式选图优先，自动候选按作者顺序；默认一轮自动展示一张，同张图片不连续自动展示，下一次明确请求可再次展示。停止或失败的半截回复不自动触发。条目条件和冷却的编辑入口放在图片详情，不铺满卡片列表。

世界书文字触发与插图展示触发职责不同：前者生成前准备资料，后者生成后决定展示。可以复用条件判断基础，但不能共享一条不断互相触发的执行循环。图片展示不调用模型工具、不修改剧情状态；模型显式选择图片时仍遵守所处权限。

本轮所选资源、对应消息分支及图片版本真实保存；重新打开不重选、不重新随机。重新生成回复属于另一分支，不改旧回复的插图。文件缺失显示可恢复的失败，正文保留。

**验收**：用户能在卡片预览条件效果；剧情满足条件后出现正确图片；多个命中结果稳定；停用书中的图不可被选；换分支和重开显示原图；图片不反复触发请求。随机候选、朋友圈式模板和复杂图文排版在此链路通过后再扩展。

## 8. 代码职责和执行顺序

不再把新增规则放进越来越长的聊天状态文件。拟按真实职责形成边界：

| 边界 | 输入和输出 | 复用位置 |
| --- | --- | --- |
| 仓库入口解析 | 草稿／对话入口 → 已保存的仓库地址 | 当前导航、准备文件与导入服务 |
| 选择流程状态 | 选择草稿、当前目录 → 保存／取消一次结果 | 现有创作库与共用选择弹层 |
| 世界书采用 | 卡片引用、开关与修订 → 本局采用配置 | 卡片引用、配置命令与快照装配 |
| 世界书评估 | 冻结条目、可见消息和总预算 → 采用正文与原因记录 | 现有触发器和来源记录；不承担工具审批 |
| 卡片目录提交 | 标准卡片修订与附件 → 可恢复的数据库／文件一致结果 | 工作区命令、媒体事务与导出 |
| 插图展示 | 本轮正文、候选及选择 → 已保存图片消息内容 | 现有消息分支、图片渲染和媒体保留 |
| 服务请求适配 | 已识别服务及请求环境 → 专属请求配置 | 实际服务构建入口，不污染所有兼容服务 |

推荐交付顺序：

1. **维护候选包**：固化上一批已有修复 → 复现修复仓库与弹窗 → 核对目标模型服务 → 局部交互修正 → 白鸽桌面验收 → 升级回归。审批暂缓项仍明确列出，不称所有批准交互已完成。
2. **世界书复用候选包**：默认选择、模块范围、开关、通用触发、本局采用、标准工具、实际来源记录一起交付。先用已有数据库和引用完成，不等待卡片目录迁移。
3. **卡片资源候选包**：独立目录协议和迁移验证 → 模块添加图片 → 复制／删除／交换／旧局保护完整验收。
4. **剧情插图候选包**：条件展示和按语境选图 → 消息持久化 → 预览和分支回归；模板另行迭代。

长资料质量线在仓库读取恢复后继续，不阻塞无关维护修复；同样不因维护包发布而标通过。每批以完成标准估算实际工作量，不承诺未经复现的固定日期。发现基础断点则先关闭断点，不用追加界面绕路。

## 9. 发布与验收门槛

- 每个新故障先有能捕获原症状的最小失败过程，再修复并重跑；没有复现时报告“未定位”，不能从代码推断宣布修好。
- 首选既有安卓快速检查通道，针对相关边界测试；通过后构建候选包，在独立安卓 14 环境走真实点击。补一台用户实际机型验证触摸、键盘和桌面图标；设备不可用则写明未覆盖。
- 完整中文旅程：仓库导入三份资料 → 人工智能找到并读取 → 创建多张卡 → 回答打开 → 精确修改一模块 → 选角色 → 启动文游 → 选择两本书并关一本 → 查看状态 → 存档 → 重开续接；图片批次再接添加、展示、导出与恢复。
- 检查三档权限、取消、重复点击、网络失败、写入失败、返回与重开；只读没有工具也不能声称写成功。运行中的身份／设定变更不污染旧请求。
- 真实模型理解验收与可控服务的软件验收分开报告；模型选择对一个工具不等于实际数据链路全部通过。
- 不污染用户现有数据；迁移先备份并有明确恢复步骤；原对话包和测试私密内容不随版本发布。
- 每批交付：变更说明、失败及修复证据、前端截图、相关测试、未覆盖项、可回退方式。发布前再按最新版本确定版本号，计划书本身不构成上传发布操作。
