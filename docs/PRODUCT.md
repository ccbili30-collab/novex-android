## 卡片模型

只有两种卡类，共用同一套模块化内容底座：

- **世界卡**：提供世界背景与设定，可直接开始对话（不需要先建角色卡）；
- **角色卡**：提供角色人格，可独立使用，也可作为世界内角色被引用。

卡片必须支持：人工创建与编辑；模块新增、删除、排序；横向与竖向模块；模块嵌套；图片资源；预览与保存；导入与导出；删除；AI 读取和修改。

导入导出要求：

- 外部未知卡片若不能可靠解析，整体原文进入自由文本模块，**不得**强行拆成"概述""姓名"等字段；
- 原生 Novex 格式必须完整导出、完整还原，包括模块顺序、嵌套关系、图片、世界内角色和必要扩展信息（规范见 `docs/specs/card-format.md`）。

## 核心原则

1. **卡片编辑与卡片使用分开**。使用资料不自动等于拥有修改权限。
2. **背景注入、角色身份和管理权限分开**。世界卡给背景设定，角色卡给人格；管理权限只授权 AI 修改指定卡片或模块，不会自动把全部管理内容注入对话。
3. **模式不是卡类**。模式属于对话运行时；当前优先保证标准场景，不擅自增加多模式和分对话系统。
4. **暂不做分对话**。主线是让一条普通对话完整稳定：创建/导入卡片 → 预览 → 编辑 → 保存 → 互动 → 读取卡片 → AI 修改 → 查看结果 → 导出还原。

## AI 修改卡片的纪律

- 读取最新保存内容；有未保存草稿时必须明确处理；
- 同一张卡修改期间避免并发覆盖；
- 保存成功后才能报告完成；
- 完成入口必须打开真实对象（不是缓存或草稿）。

## 当前重点问题（3.0.x 方向）

1. **上下文长度**：不同模型真实上限不同（如 DeepSeek Flash 约 128K）。卡片超限时先提示"内容超过当前模型可用上下文"，允许减模块/降携带/压历史；不重复发送同一失败提示；调整额度后重算请求；无法压缩时退出循环并保留待发送内容。
2. **压缩与记忆**：向 Pi 式记忆压缩演进——保留大部分原始信息，压缩的是历史组织方式；重要历史可回溯；摘要区分事实、设定、用户要求、未完成任务、推测；不破坏剧情或卡片原文。
3. **流式输出**：正文边生成边显示；工具过程与结果可折叠但不得吞掉正文；错误不顶走界面；用户上翻时保持阅读位置；生成结束不跳回顶部；中断可继续；失败不卡"正在执行"。
4. **工具调用循环**：模型回复 / 工具调用 / 工具返回 / 数据更新是不同事件；支持多轮循环、用户中断、权限确认、失败恢复；不允许只显示"已执行"而不展示实际做了什么。
5. **选择按钮**：不依赖 Markdown 周边文字推断。使用显式选择事件结构（label/value/order 的 JSON 数组）。
