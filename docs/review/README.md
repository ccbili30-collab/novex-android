本文件把 Codex 继承技能、项目自有资产和审查代理接成一条流水线，是 `docs/WORKFLOW` 分级审查环节的执行细则。
参考技能原文在 `reference-skills/`（逐字继承自 Codex 技能目录，未改写）。

## 三个审查代理（Agent 工具派发，审查者不改代码）

**A. 源码对比审查（中/重级启用）**
指令骨架：给定本轮需求 + 已确认产品规则 + 改动 diff + 对应参考技能全文 + 项目锚点。
重点：实现是否贴近参考技能定义的成熟形态；是否重新发明仓库已有机制；UI 层级/字号/间距是否符合设计系统与组件契约。

**B. 整体链路审查（中/重级启用）**
指令骨架：给定链路图（操作→界面→ViewModel→领域→仓库→库→AI→事件→渲染）。
重点：新功能是否接对最上级入口；新旧两套逻辑是否并存；数据唯一来源；修复是否破坏其他链；循环依赖与隐式状态；旧格式兼容是否污染新业务。

**C. 修复后独立复查（重级启用）**
指令骨架：给定最终 diff + 前两轮意见清单。不默认相信已修好：逐条核对意见是否真处理、是否产生新副作用、遗漏、与最终行为不一致。

## 主 Agent 检查单（每轮必过，顺序执行）

1. 范围五问（现象/理想/本轮修/顺带修/保留）已获用户确认；
2. 本地机械自检：`scripts/tests` 契约测试通过、无未用/缺失导入、可空标注核对、组件禁用清单扫描；
3. 语义自查：正常路径、空数据、旧数据、中断/失败/重启恢复、重复触发、覆盖用户内容、导航返回、删除/导出/撤销；
4. UI 改动：渲染推演（坐标/触达区/状态机逐转换）附在提交说明；
5. 分级正确：轻/中/重的代理启用数与任务文档声明一致。

## 意见处理与责任

审查意见三分类：确定缺陷直接修；可能风险读码或加验证；产品取舍交用户。意见与用户已确认结构冲突时拒收并说明。主 Agent 维护统一上下文、裁决意见、完成修改、对完整链路和交付结果负责。
