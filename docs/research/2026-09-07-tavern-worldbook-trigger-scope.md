# 酒馆世界书：最小触发范围核对

核对日期：2026-09-07。对象：SillyTavern（傻酒馆）官方文档、发布分支源码，以及 Character Card V2/V3（角色卡第二／三版）原规范。本文件是实现建议；未修改产品代码、未运行模型接口、未访问用户密钥。

**建议交付“角色版本快照内的世界书基础触发”，不承诺完整酒馆运行兼容。** 原件完整保留与运行执行分开：只执行明确支持且通过校验的条目；缺失条件、未知运行扩展、脚本依赖等逐条标记“已保留，未执行”。任何解析失败或暂不支持，都不能把正文降级成常驻全文。

## 已直接验证的现状与边界

当前 [酒馆转换器](../../src/android/app/src/main/java/com/openminis/app/novex/domain/NovexTavernExchange.kt) 保存原始数据到 `_novexTavernSource`（酒馆来源归档），只把角色描述等已知字段映射成模块，没有执行世界书。它导出时会把部分原生公共模块附加为常驻世界书条目，但这不能反推“导入世界书应全部转为公共常驻模块”。玩家身份没有被默认为接收方玩家，此约束应继续继承。

第二版规范要求未知扩展与未支持可选字段不被销毁；第三版规范也要求保留可选字段以安全导出。第三版同时对停用、正则和修饰指令有更具体的运行要求，因此“能读入第三版文件”不等于“实现第三版运行规范”。[第二版原规范](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)、[第三版原规范](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)

## 建议执行映射

下表均为**拟实现规则**。字段仍原样归档；执行层建立独立的规范化记录和不执行原因，不回写原件。字段类型不合法时暂停该条目，不能用宽松真假转换修复作者条件。

| 原字段或行为 | 第一阶段执行范围与规则 |
| --- | --- |
| `enabled`（启用） | 必须是布尔值；只有明确为真才进入评估。假值无条件跳过，包括常驻条目。缺失视为无效条目并报告。 |
| `constant`（常驻） | 缺省为假；明确为真可免除主次关键词匹配，但不能免除停用、未支持条件、预算等检查。 |
| `keys`（主关键词） | 字符串数组，任一非空纯文本关键词命中即满足主条件；每条正文只注入一次。非常驻且没有有效关键词时不激活。不能把空关键词传给子串匹配。 |
| `scan_depth`（全书扫描深度） | 采用条目 `extensions.scan_depth`（扩展扫描深度）→全书深度→明确写入快照的本地默认值，建议默认 2。仅接受非负整数；超出产品上限应提示并暂停采用该设置，不静默扩大范围。0 表示不扫描聊天正文，常驻仍可候选。 |
| `case_sensitive`（区分大小写） | 建议扩展 `extensions.case_sensitive`（扩展大小写设置）→标准字段→快照默认假。两处明确冲突时暂停条目并展示冲突，不能无声选边。大小写转换须固定规则，不受设备地区设置影响。 |
| `extensions.match_whole_words`（扩展完整词匹配） | 支持明确的真／假，缺省假并记录在快照。若复刻傻酒馆：包含空白的多词短语仍做整段子串匹配；单词两侧使用非英文字母、数字、下划线边界。不要直接换成平台默认的 Unicode（统一字符编码）词边界而声称等价；中文不会获得中文分词能力。 |
| `selective`（次关键词筛选）、`secondary_keys`（次关键词） | 假值忽略次关键词；真值且有非空有效数组时，主条件与次条件必须同时成立。建议真值但次关键词为空时暂停条目：傻酒馆忽略空筛选，而第二版字段注释要求两边都有关键词，此处不静默猜测。 |
| `extensions.selectiveLogic`（扩展筛选逻辑） | 可低成本一次支持四种：0＝主条件且次关键词任一命中；1＝主条件且次关键词并非全部命中；2＝主条件且次关键词全部未命中；3＝主条件且次关键词全部命中。缺省 0；未知枚举暂停条目。只支持 0 的版本须暂停其余逻辑，不能把它们都当成“任一”。 |
| `insertion_order`（插入顺序） | 正文按数值升序排列，小值在前；同值按原数组顺序稳定排列。不是激活条件。不要把“预算优先选较大值”误当最终正文降序。 |
| `position`（插入位置） | 支持 `before_char`（角色定义前）与 `after_char`（角色定义后），分别落在角色定义块的真实前后锚点；缺省后方并在快照显式记录。傻酒馆 `extensions.position`（扩展位置）0／1可映射上述两处；与标准字段冲突则暂停。其他位置暂停，不一律挪到末尾。 |
| `token_budget`（词元预算）、`priority`（优先级） | 全书预算及产品上下文额度都要生效；预算为 0 不注入。逐整条选择，不能截半段正文。建议常驻优先，再按显式优先级／插入顺序选取，最后按位置和插入顺序排版；具体预算算法属于本地范围，不声称完整复刻酒馆。需记录溢出跳过原因；未能准确计数时明确采用的估算方法。 |

上述规范字段含义见 [第二版原规范](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md) 与 [第三版世界书定义](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md#lorebook)。傻酒馆实际转换函数 `convertCharacterBook`（转换角色世界书）、关键词匹配、四种筛选枚举及插入流程见 [官方世界书源码](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)；用户层解释见 [官方世界书文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)。

### 扫描范围必须固定

深度是**单条消息数，不是用户与角色的一对回合**。正常发送时包含本次用户输入与此前角色回复；只扫描本局、当前分支、当前采用快照范围内最近的这些消息。重试／重新生成时不能把被替换的旧回复算进去。第一阶段建议只扫描对话可见正文，排除系统指令、工具消息、管理原件读取结果、其他角色资料、其他玩家身份、已注入世界书、附件与推理过程；这些是本地明确收窄的范围。

直接源码证据：生成流程构造 `coreChat`（核心聊天），对消息加工后反向传给世界书；它还可包含工具调用消息、附件文本等，因此不能宣称上述本地范围与其全部相同。酒馆可给消息增加说话者名前缀，第一阶段建议不添加此前缀；以后支持时只能使用本局快照绑定的双方显示名。[官方生成流程源码](https://github.com/SillyTavern/SillyTavern/blob/release/public/script.js)、[扫描深度与包含名称文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/#scan-depth)

不要把原始数据全文当匹配文本，也不要仅扫描最新用户输入后宣称支持深度。例：最新消息为“继续”，上一条角色回复含“港口”，深度 1 不命中“港口”，深度 2 才命中。

## 先保留、暂不执行的能力

| 能力 | 原件保留；运行处理 |
| --- | --- |
| 递归 `recursive_scanning`（递归扫描） | 第一阶段只做一次聊天扫描，不把命中正文重新送回触发器。第三版允许选择不执行递归；需要标示“仅直接触发”。`exclude_recursion`（排除递归）与 `prevent_recursion`（阻止继续递归）在单遍中无额外效果；`delay_until_recursion`（延至递归激活）为真／正数的条目必须暂停，不能直接触发或常驻。 |
| 概率 | 有效概率为 100%／明确关闭概率时可按确定性条目执行；开启且为 0% 时不激活；1%—99% 第一阶段暂停，不能忽略概率当每次命中。 |
| 分组 | 非空 `group`（纳入组）及组选择／评分依赖暂不执行，暂停所有受影响条目，不能同时注入互斥候选。空组、未启用的默认权重等可判为无效配置，不必仅因字段存在暂停。 |
| 持续、冷却、延迟 | 正值 `sticky`（持续激活）、`cooldown`（冷却）、`delay`（延迟）暂停；缺省／0不产生运行约束。不能让常驻跳过冷却。 |
| 更多位置 | 作者注释前后、示例对话前后、指定聊天深度及 `outlet`（命名输出位置）暂停。尤其命名输出位置原本不是自动注入，挪到常驻正文会改变行为。 |
| 正则 | 第三版 `use_regex`（使用正则表达式）为真，或傻酒馆 `/模式/标记`（斜杠包围的正则关键词）暂不执行。混合普通与正则关键词的条目也暂停，不能把缺失的负向筛选绕开。 |
| 第三版修饰指令 | 正文头部 `@@`（修饰指令前缀）相关条目暂停，包含禁止激活、延迟、额外关键词、角色及位置覆盖等。先完整保留，不剥除指令后照常注入。第三版允许忽略未知修饰指令；这里选择更保守的局部兼容策略。 |
| 宏 | 第一阶段不替换 `{{…}}`（宏占位符）；关键词／正文含宏的条目暂停并报告。若下一阶段只支持 `{{char}}`（角色名）和 `{{user}}`（玩家名），须只从当前已采用快照取值，不能从全局玩家身份、临时编辑草稿或另一个角色取值；第三版 `nickname`（昵称）也须确定优先级。其他宏仍不得被顺带执行。 |
| 脚本／自动化 | 非空 `automation_id`（自动化标识）及第三方脚本依赖暂不运行，相关条目暂停。禁止导入触发脚本安装、网络请求、状态修改或调用模型工具。源码会先替换关键词及内容中的宏，文档还允许条目触发快捷回复脚本，因此只保存字符串不等于这些行为已实现。 |
| 其他运行扩展 | 向量激活、角色／生成类型过滤、额外匹配来源、跳过预算等非默认配置均暂停；已知纯元数据可放行。未知扩展无法证明只是元数据时先暂停相关条目，书级未知运行配置则暂停本书；不能盲目忽略它并把剩余正文激活。 |

递归与修饰指令根据 [第三版原规范](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)。概率、组、计时、脚本、额外扫描源和插入位置根据 [官方世界书文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/) 及 [官方运行实现](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)。这里的“暂停”是 Novex（诺瓦项目）为避免扩大触发而提出的产品选择，不是声称原规范要求所有客户端这样做。

## 快照、隔离与最小验收

采用角色版本时，把来源摘要、条目原序号／标识、解析结果、明确默认值、兼容范围版本及玩家身份绑定写入采用快照。发送只读该快照；资料库后续修改不会自动改变进行中的本局。重新采用才更新。导入归档本身不表示采用，不自动绑定全局世界书，也不替换角色专属玩家身份。这是本项目约束，不是酒馆原规范承诺。

每次评估至少能解释“停用／范围外／未命中／次条件不满足／未支持／预算不足／已注入”以及对应条目来源；原件只能在明确管理路径读取。拟实现后应验证：停用常驻不注入；无词非常驻不注入；深度 0／1／2边界；四种次条件；大小写及中英文完整词；预算不超额；位置顺序稳定；概率／递归延迟／未知宏不会降级常驻；换角色、换玩家、资料库修改不会改变已采用快照。

## 仍需明确承认的差异

- 原规范与酒馆不是同一个默认值体系。所核对的酒馆转换函数读取条目扩展中的扫描深度和大小写，未把全书标准深度或条目标准大小写直接纳入该转换；本建议的标准字段回退是本地互通选择。
- 酒馆文档称完整词匹配默认开启，所核对源码模块初始值为假，并可由用户设置覆盖；不能从角色卡恢复作者未附带的全局设置。本地默认值必须显式进入快照。
- 酒馆文档称扫描深度 0 仍可评估递归与作者注释，但所核对源码缓冲函数在深度不大于起始深度时先返回空文本。第一阶段只承诺“0 不扫描聊天正文”，不尝试恢复这类混合扩展行为。
- 第三版 `secondary_keys`（次关键词）类型声明为字符串数组，正文说明却写成逗号分隔字符串，存在规范内不一致；第一阶段接受数组形式，其他形态保留并报告，不自行按逗号拆分可能的正则。
- 来源链接是会变化的分支文档；本研究记录核对日期，未锁定提交，也没有完成跨客户端运行对照。落地时应以固定样例做确定性验证，不能把本文件当成完整兼容证明。

差异可在 [第三版原文](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)、[酒馆源码](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js) 和 [完整词匹配官方说明](https://docs.sillytavern.app/usage/core-concepts/worldinfo/#match-whole-words) 直接核对。
