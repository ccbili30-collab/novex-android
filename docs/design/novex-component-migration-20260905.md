# Novex 共享组件替换检查点

## 本轮边界

在 preview（预览工作树）的 next（下一版分支）实施。只处理产品界面的组件来源与缺口，不改世界、角色、文游、对话的数据格式，不替换模型或工具运行时，不修改正式版或版本号。用户负责设备点击；自动测试和静态检查不能冒充实机验收。

## 为什么之前换主题仍然混杂

1. 旧组件、新组件、直接调用基础框架三条路径并存。
2. 部分新组件只是旧控件的转发层，颜色变了，内部结构仍然没变。
3. 表单和选择器自行使用旧输入框装饰，绕过了入口级检查。
4. 一些页面固定字号绕过应用内字体比例。
5. 旧图标来自另一套资源，改主题无法改变线条风格。

这不是靠每个页面换一组颜色能解决的问题。保留旧函数名仅为兼容已有调用；它们不得再拥有第二套绘制实现。

## 替换映射

| 能力 | 唯一实现 | 兼容或业务入口 |
| --- | --- | --- |
| 主、次、文字按钮 | NovexButtonSurface（按钮表面） | Button、OutlinedButton、TextButton、Minis 系列、NovexPrimaryButton、NovexOutlineButton |
| 表单输入与错误提示 | NovexInputSurface（输入表面） | OutlinedTextField、DialogTextField、SectionTextField、NovexTextField |
| 菜单表面和动作行 | NovexPopupMenu / DropdownMenuItem（浮层菜单／动作行） | DropdownMenu、MinisMenu |
| 确认与表单弹窗 | NovexDialogSurface（弹窗表面） | AlertDialog、NovexDecisionDialog，以及保存／删除／通知入口 |
| 短选项、搜索、多选、分组、禁用说明 | NovexSelectionSurface（选择表面） | NovexSelectionSheet、NovexSearchableSelectionSheet、SectionDropdown |
| 勾选与不勾选 | NovexCheckIndicator（勾选指示器） | Switch、Checkbox、RadioButton；保留各自交互语义 |
| 详情、设置与编辑顶部栏 | NovexTopBarSurface（顶部栏表面） | TopAppBar、NovexPageTopBar |
| 设置分组边界 | NovexSectionSurface（分组表面） | NovexSettingsSection、SectionCard、两处 SettingsSection 兼容入口 |
| 草稿退出 | NovexDraftExitBoundary（草稿退出边界） | 世界／角色／文游编辑骨架、记忆文件编辑 |
| 页面图标 | NovexIcons（图标资源） | 174 个语义名称映射到同一套 Phosphor（磷图标库）常规线条资源 |
| 页面度量和文字 | NovexDimensions / NovexType（尺寸／字体） | 公共组件；新目录及本轮清理的固定字号使用应用字体比例 |

目录搜索继续使用已存在的即时输入与延迟过滤策略，不改变数据查询规则。地图、关系、技能等业务内容渲染器仍保持各自职责，不塞进一个万能页面。

## 填补的组件缺口

- 长选项列表采用按需创建的列表，支持搜索名称、描述、分组；无结果有明确提示。
- 多选可以连续操作后完成；禁用项显示原因，不能误触回调。
- 弹窗统一宽度、边界、文字层级和动作区；自带滚动的列表显式声明，避免嵌套无界滚动。
- 输入支持只读、禁用、错误、密码变换、键盘动作和输入法组合态；不替换聊天正文的输入状态管理。
- 顶部栏按真实动作宽度测量标题，不再统一空出一个固定的大宽度。
- 草稿的顶部返回与系统返回走同一个退出决策；保存失败不直接丢弃草稿。
- 设置增加“组件预览”入口，仅在预览应用显示，用真实共享组件展示各类状态，不读写用户创作内容。

## 有意保留与尚未证明的事项

- 保留基础框架的布局、焦点、底部面板手势、系统弹窗宿主和滑块交互；它们是底层能力，不应为了删除库名重新实现。
- 保留系统图片选择器、权限窗口、键盘，以及浏览器网页／终端内容自身的渲染。它们不受应用组件库完全控制。
- 完整会话列表仍保留批量导出、分组和模型配置入口。轻量首页不具备这些能力，不能为统一页面文件而把它们删除；本轮统一共享组件，不宣称两条业务路线已合并。
- 应用中仍可存在业务专用布局。静态禁止旧控件入口不等于已证明所有留白、字号、长内容和设备表现一致。
- 本轮没有设备点击、截图比对或真实输入法验收；视觉复刻度与触控行为由用户检查，不标记为“完全还原”。
- 专用日期／时间选择器、少数旧路线的扩展悬浮按钮与选项卡仍需专门迁移；本轮门禁覆盖的是清单中的常用控件，不把未覆盖类别记成已替换。下一批应按这个清单处理，不让用户逐页截图寻找。

## 回归门禁

- scripts/check_novex_ui.py：检查直接导入、别名、全限定调用、通配导入、旧图标和旧输入装饰。
- scripts/tests/novex_ui_boundary_test.py：检查门禁本身，防止换个调用写法就绕过。
- NovexComponentArchitectureTest（组件架构测试）：随安卓单元测试执行，检查组件来源与兼容入口。
- NovexSelectionPolicyTest（选择策略测试）：检查搜索和禁用项行为。
- NovexHeaderGeometryTest（顶部栏布局测试）：检查窄宽度下标题不覆盖两端动作。
- NovexIconAssetsTest（图标资源测试）：解析全部图标，验证实际路径非空，避免只有名称正确。
- 已有编辑退出、导航、外观与领域测试继续运行。

## 用户验收入口

先从设置的“组件预览”看输入、单选／多选、禁用项、长表单、错误状态和保存／删除确认是否使用同一语言；再检查实际路径：

1. 设置 → 外观／模型 → 搜索、选择、勾选与弹窗。
2. 会话 → 右上角菜单 → 对话编辑；消息菜单的删除动作。
3. 世界／角色／文游 → 编辑 → 修改 → 返回确认；预览返回保留草稿。
4. 设置 → 记忆 → 文件编辑 → 修改 → 返回确认。
5. 切换应用字体大小、浅深色，检查顶部动作、长名称、软键盘和长列表。

本文件记录来源收口检查点，不作为上述设备路径已经通过的证明。
