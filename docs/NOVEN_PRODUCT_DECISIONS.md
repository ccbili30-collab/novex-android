# 诺文玩家模式：已确认产品决策

本文是实现约束，不是待讨论的提案。后续修改若与本文冲突，必须由用户明确确认。

## 产品边界

- 当前只实现玩家模式；创作工作台暂缓。
- 产品以人工智能对话为主，但世界发现、世界详情和会话切换必须是稳定的一等入口。
- 用户可选择公开世界游玩，也可从一句灵感创建自己的世界。
- 公开世界由“开始模板”驱动：作者既可以只给框架，也可以给出完整人物与开场。
- 发布权限分为仅展示、世界不可改但可编排剧情、开放改造三种。
- 本地游玩是独立副本，不反向修改作者发布的世界。
- 第一阶段只做本地存储；公开分享、社区与复杂导出暂缓。

## 信息结构

- 根层是同一主界面中的“世界 / 对话记录”左右分页，不再设置传统底部主导航。
- 默认打开“对话记录”；用户可横向滑动或点击顶部标签切换到“世界”，切换后必须保留各自的滚动位置。
- “世界”展示推荐世界和继续游玩入口；进入世界详情后再开始新的玩家会话。
- “对话记录”以封面头像、故事标题、最近一句和时间组成列表，并提供新建故事入口。
- 进入对话后可从侧边抽屉直接切换会话，不要求返回首页。
- 对话标题由人工智能概括一次后保持不变，除非用户或专用工具明确修改。
- 点击对话标题进入世界资料；资料不是第三种人工智能模式。
- 设置从根界面右上角进入，只呈现人格、记忆与技能；模型上下文协议、运行环境、沙箱和存储等工程能力在普通界面隐藏。

## 对话与渲染

- 人工智能不被固定文本模板约束；产品通过工具提供标准内容节点。
- 小说正文必须使用正文节点渲染，不得混入普通聊天气泡。
- 用户消息、人工智能叙事、角色卡与行动建议必须具有不同的语义表面，避免把整个会话渲染成一篇连续正文。
- 首批节点：正文、角色卡、世界物件、简化地图、行动按钮、会话元数据。
- 行动按钮只把文字填入输入框，绝不自动发送。
- 角色卡允许异步补充画像。
- 地图先生成简单像素网格结构，再交给图像模型美化；只保留少量可点击地点。
- 选择正文可添加标注；标注作为输入框上方的结构化附件发送，不粘贴进正文。
- 正常界面隐藏原始工具日志；面向用户的错误全部使用中文。

## 事实与上下文

- 工具调用产生的角色、地点和关系自动形成资料视图，不要求模型重复抄写档案。
- 后台只整理已经写出或明确由工具产生的事实，不制造隐藏状态。
- 资料页展示模型已经产生的内容，不做传统游戏式隐藏解锁。
- 上下文由近期对话、滚动摘要和按需检索的本地资料共同组成。
- 必须保留“模型 → 工具 → 结果 → 模型”的循环调用能力。
- 每个会话预留用户写作提示词位置，例如“你是一位文笔细腻的作家”。

## 移动端行为

- 手机始终只有一个主表面；次级内容使用抽屉、独立页面或底部面板。
- 对话正文区域滚动，顶部栏与输入区固定；不得把整套对话界面做成一张纵向长页面。
- 输入区跟随真实软键盘和可视视口移动。
- 中文输入法候选确认不得触发发送。
- 返回键依次关闭输入法、弹层、详情页，最后才离开当前任务。
- 生成过程中停止按钮始终可达；用户主动向上阅读时不得强制拉回底部。
