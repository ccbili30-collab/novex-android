# 文游制作机

把一个题材变成一张"导入即玩"的世界卡。产出物不是一篇规则书文档，而是**一张结构化的卡**：引擎与常驻设定是 always 模块，事件与人物数据库是关键词/manual 模块，开局与结局按需调用。

制作前必读（按顺序，用文件读取能力逐个读取本 skill 目录下的这些文件，读完再动手）：
1. `/var/minis/skills/wenyou-maker/references/engine.md` —— 引擎宪法与每轮注入通用段（直接复制进卡片的成品文本）
2. `/var/minis/skills/wenyou-maker/references/pack-template.md` —— 题材包七插槽决策与必填内容表
3. `/var/minis/skills/wenyou-maker/references/database.md` —— 事件池/人物卡/目标卡产卡规范（索引卡模式）
4. `/var/minis/skills/wenyou-maker/references/acceptance.md` —— 验收清单、黑名单写法、黄金回合样本要求

## 第一步 · 问卷（分步，禁止一次铺开）

每次只问一个问题，等用户回答再问下一个：
1. 题材确认：IP 名或原创世界观？偏向还原原著还是自由改写？
2. 玩法基调：战斗成长 / 生存压力 / 经营建设 / 日常多线 / 无限流副本？
3. 篇幅档位：简洁版（1.5-4万字级内容量）/ 标准版（5-8万）/ 百科版（10万+，仅用户明确要求）
4. 尺度与内容边界；是否需要可攻略人物线。
5. 是否附带独立角色卡（默认：不附带，NPC 人格写进世界卡；用户要求才建角色卡）。

## 第二步 · 调研题材

- 基于已有知识整理：力量/生存体系、势力与生态、关键人物、时间线、经典事件。
- 有联网能力时可搜索核对关键设定；**不确定的内容一律标注【推演】**，不冒充原著设定。
- 先填七插槽决策表（见 pack-template.md），想清楚再动笔。

## 第三步 · 建卡（工具调用序列）

用 `create_card`（kind=WORLD）建卡后，按下面的标准模块结构逐个 `add_module` / `add_child_module` + `write_module_text` 写入，并用 `set_module_options` 设携带规则：

| 模块 | 携带规则 | 内容 |
|---|---|---|
| 00·启动说明 | manual | 用户组装三步（见下"交付"） |
| 01·引擎宪法 | always | references/engine.md 宪法全文，替换{世界名} |
| 02·每轮注入【复制我】 | manual | references/engine.md 通用段 + 本题材段（≤3000字符） |
| 03·世界观与法则 | always | 世界一句话 + 核心真相分层 + 世界法则表 |
| 04·力量与成长体系 | always | 阶段表 + 属性表 + 成长公式（带算例） |
| 05·资源与经济 | always | 核心资源表（含归零后果）+ 锚点表 |
| 06·时间与死线 | always | 时间推进规则 + 面板可见的倒计时死线 |
| 07·势力与生态 | always | 交互矩阵/生态链表 |
| 08·开局流程 | manual | 难度表 + 模式ABC + 出身表 + 分步问卷 + 序章剧本 |
| 09·结局系统 | manual | 结局库表 + 结算评价 + 死亡处理 |
| 10·红线黑名单 | always | ≥20条题材语境反例，每条带"改做" |
| 11·总索引 | always | 事件/人物/地点/目标四张索引（每行 ID+名称+一句话） |
| 12·事件池 | manual（子模块可设关键词） | ≥100条一行式事件，按5-8类分子模块 |
| 13·人物与物种 | 关键词（人名/物种名） | ≥15张卡：立场/实力/性格/雷点/时间线限定 |
| 14·地点详卡 | 关键词（地名） | ≥10行地点表对应详卡 |
| 15·目标与任务 | manual | ≥20张三档目标卡 |
| 16·黄金回合样本 | manual | 本题材完整一轮范本（输入→骰值→判定→账本→七段输出） |

写模块的纪律：
- 先写常驻模块（00-11），再写数据库模块（12-16）；**索引先行**：先写好 11·总索引，详情卡与索引 ID 严格对应。
- 表格一律用 Markdown 表；数值必有公式，公式必有算例；禁止"酌情""尽量"类模糊条款。
- 事件条目一行式：`ID. 情境一句话（可选行为以/分隔）`，不预写结果。
- 大模块先 `add_module` 再 `write_module_text`；一次写不下就分多个文字块，**写完必须回读校验**（read_card），失败不得宣称完成。
- 高危设定（秒杀线、时间线限定、归属）在正文里用**加粗**标出。
- 角色卡：仅当用户在问卷第5步明确要求时，用 `create_card`（kind=CHARACTER）为核心 NPC 建独立角色卡，人格字段与 13·人物卡 同源。

## 第四步 · 验收（全部通过才交付）

按 references/acceptance.md 的清单逐项核对（二值判定），并：
- `read_card` 回读全部模块，抽查 5 个 ID 的 索引→详情→引用 三方一致；
- 用 `wc` 类能力核对 02·每轮注入 总长 ≤8000 字符；
- 自检结果如实写进 00·启动说明 末尾的"制作自检"小节。

## 第五步 · 交付

给用户一段组装说明（同时写进 00·启动说明）：
1. 从卡库打开这张世界卡 → 用它开始新对话（世界卡提供背景与设定）；
2. 打开对话设置 → 每轮注入 → 复制 02·每轮注入【复制我】模块全文贴入；
3. 打开同页的两个开关：骰值注入、账本回传（文游运行时）；
4. 回到对话说"开始游戏"，按 08·开局流程 的分步问卷开局。

交付时明确告知：本卡适配骰值注入（每轮2枚1d100）与账本回传（每轮末尾<账本>块回传）；宪法与注入文本中已内置对应协议，无需额外配置。

## 红线（制作侧七禁）

1. 不得照抄任何现有商业规则书的内容段落；引擎骨架用本 skill 的 references，内容必须原创转译。
2. 不得给玩家"无失败可能的收益"。
3. 死线必须进面板（06 模块的面板行）。
4. 不得让单模块超过 3000 tokens；超了就拆子模块。
5. 输出结构只有一种：七段输出 + <账本>块（见 engine.md）。
6. 不得省略 10·红线黑名单 与 16·黄金回合样本——它们是运行质量的保险。
7. 与引擎宪法零冲突：不得出现"面板可因剧情修改"类条款。
